# 灵动岛工作台：DSH 新一代交互方案

> 目标：把「打开一个面板看四个页面」改成「一堆可自由拼装的原子组件，围着一个岛转」，并且**任何 DSH 插件都能变成原子**，**Agent 能直接改这个界面**，**界面可以由模型生成**。
>
> 本文是调研 + 方案，不是已完成实现。文末给出与现有办公工作台（`dsh-work-desk`）结合的分阶段落地路径。

---

## 1. 调研：三个仓库各自解决什么

### 1.1 FullWidget（Windows 桌面小组件，38 个内置）

它证明了一件事：**把"组件"当成一等公民，需要一个明确的组件契约，而不是一堆硬编码页面。**

可借的：

- **组件包结构**：`widget.json` + `index.html` + `main.js` + `style.css` + `icon.svg`。manifest 里声明 `id / name / version / entry / icon / size{width,height,minWidth,minHeight,grow} / permissions / settings[]`。
- **权限模型**：`system | notify | audio | media | shell.open | shell.launch | network:<host>`，第三方组件在安装时列出、用户逐条同意；`fetch` 由宿主代发并做 host 白名单，绕开 CORS 同时可审计。
- **设置即表单**：`settings[]` 声明式（text/toggle/…），控制中心自动生成表单，组件只读 `widget.settings.get()`。
- **每实例存储**：`widget.storage.get/set`，删除实例即删数据。
- **主题与外观解耦**：`appearance{theme, style, shadow, themeCss, userCss, values}`，组件通过 CSS 变量吃主题。
- **组件事务性能力**：`notify`（可预约到 7 天内，宿主在页面暂停时也能送达）、`window.setSize/startDrag`、`t()` 多语言、`on('settings'|'appearance'|'state')` 事件。
- **市场与开发模板**：新增组件 = 复制模板目录，不碰宿主。

不适用于 DSH 的：它是 WebView2 桌面壳、桌面层叠；我们不需要窗口管理，需要的是**在 Web GUI 内的可拼装布局**。

### 1.2 dsh-widgets（DSH 原生组件栏）

它证明了一件事：**DSH 插件完全可以承载一个"组件生态"**，关键是让组件单元可被构建期发现、运行时装配。

可借的：

- **组件单元 + 构建期注册**：`src/widgets/<id>/{manifest.json,index.ts}`。manifest 是机器可读的一半（`id/order/group/builtin/defaultInstalled/sizes/source/skeleton` + 该组件自己的 locale），`index.ts` 用 `defineWidget` 给**纯数据的 render 模型**、名称/描述 thunk、`configSchema`、`example`。注册表由 `scripts/gen-registry.mjs` 扫描生成，禁止手工维护，未知 manifest 键直接报错。
- **契约零依赖**：`client/lib/contract/types.ts` 不 import 任何东西，只想拿类型的消费方不会把 React/i18n 拖进模块图。
- **尺寸档位**：`sizes: ["2x2","2x4"]`，卡片边长按 10px 量化、夹在"5 行可见"上限内——同一套栅格逻辑可以搬到岛上。
- **空间契约**：组件栏从不索取固定宽度，而是读产品自己发布的变量算预算，放不下才让位。**这个纪律必须继承**：岛不能挤压对话正文。
- **放大波**（`WAVE_SPRING` + 逐帧写样式）、骨架屏、连续曲率圆角、开关动画——观感层的现成答案。
- **数据源与卡面分离**：`client/families/<族>/{data,renders}.ts`，族间不互相引用；host 侧一个上游一个模块 + `host/http.ts` memo + 唯一子进程缝 `host/exec.ts`。
- **Slot 接入**：`conversation.input.overlay`（抽屉/浮层，刻意放对话子树以便被右栏面板吞掉）、`conversation.session.header.utilities`（胶囊，注意 order 撞号）、`settings.section`。

局限：它的组件是**只读仪表盘**，布局固定为列、组件不开放给第三方插件、Agent 不能改界面。

### 1.3 dsh-web（DSH Web 插件全家桶）

它证明了一件事：**界面只要由宿主权威驱动，Agent 就能安全地读写。**

可借的：

- **宿主权威（Host-authoritative）**：看板的卡片流转、调度、执行监控全在 Host 进程，前端只是视图；状态持久化在 `profiles/web/*.json`，换 origin、无痕、清站点数据都丢不了。**岛的状态必须这样存。**
- **面向 Agent 的工具面**：一个 UI 能力同时暴露 8 个原生工具（`task_board_list/get/create/update/...`），模型能"用嘴改界面"。
- **外部提供方契约**：GitHub / 团队 / 远端三个扩展按标准契约挂载，不需要改核心。
- **PTC（Programmatic Tool Calling）**：把上百个 JSON Schema 收拢成唯一 `run_code`，MCP 工具走"温和分页 + LRU 激活"。这与我们此前踩过的"PTC 下执行器只公布 run_code"完全对应——**插件适配器必须同时兼容原生工具面和 PTC 面**。
- **权限基线 + 人工确认门 + Fail-Closed**：钉住工作区/预设/沙箱/模型，超出基线要人确认。

局限：它是"功能插件集合"，每个功能自带整页；没有统一的组件模型，也没有"任意插件 → 原子"的桥。

## 2. 结论：DSH 缺的那一层是「原子层」

三家合起来，正好是三个缺口的拼图：

| 维度 | FullWidget | dsh-widgets | dsh-web | 我们要补的 |
|---|---|---|---|---|
| 组件契约 | ✅ 完整（含权限） | ✅ 构建期注册 | ❌ 每插件一页 | 统一 Atom 契约 |
| 宿主权威 | ❌ 本地 | ✅ 状态文件 | ✅ 看板 | 岛状态 Host 权威 |
| Agent 可改 UI | ❌ | ❌ | ✅ 看板工具面 | **`island_*` 工具** |
| 任意插件变原子 | ❌ | ❌ 只读内置 | ❌ | **插件适配器** |
| 生成式 UI | ❌ | ❌ | ❌ | DSL + 沙箱 |
| 空间纪律 | n/a | ✅ | n/a | 岛不挤正文 |

**一句话方案**：在 DSH 里加一个 **Island Workbench** 宿主插件，它维护「原子注册表 + 布局 + 实例状态」，向三边开放：

- 对**用户**：可拖、可调档、可换主题的灵动岛（收起是一行胶囊，展开是栅格）；
- 对**插件**：`atoms.json` 声明即接入（零代码），或自动退化为"工具卡原子"；
- 对**Agent**：`island_*` 工具面 + 生成式 DSL，一句话重排/新建/生成卡片。

现有 `dsh-work-desk` 是这个方案的**第一个参考实现**：它已经有 store/ops/receipt/undo、5 个语义工具、Host 路由和会话镜像，正好当"原子层的宿体"。

## 3. 架构

```
┌───────────────────────────── Client (web) ─────────────────────────────┐
│  IslandShell                                                           │
│   ├─ IslandStrip   （收起态：一行胶囊，3–5 个原子，横向滚动）           │
│   ├─ IslandGrid    （展开态：栅格 + 放大波 + 拖拽 + 尺寸档位）          │
│   ├─ AtomHost      （按 manifest.kind 分发：native / plugin / generated）│
│   └─ AtomSandbox   （iframe + SDK 桥：settings/storage/fetch/notify）    │
└───────────────────────────────┬────────────────────────────────────────┘
                                │  JSON-RPC /work-desk/island/*
┌───────────────────────────────▼────────────────────────────────────────┐
│  Host（权威）                                                          │
│   ├─ AtomRegistry   （构建期发现的 builtin + 运行期注册的 plugin 原子）  │
│   ├─ LayoutStore    （island.json：布局/尺寸/顺序/主题，原子级 diff）    │
│   ├─ DataBroker     （原子声明的 reads → 宿主取数、缓存、TTL）           │
│   ├─ OpsLog         （applyOps 白名单 + 回执 + 撤销，复用现有实现）      │
│   └─ Tools          （island_* 6 个工具 + atom 自定义工具）             │
└────────────────────────────────────────────────────────────────────────┘
```

### 3.1 Atom 契约

```ts
type AtomSize = '1x1' | '2x1' | '2x2' | '2x4' | 'full'

interface AtomManifest {
  id: string                    // 命名空间化：work-desk.calendar.today
  kind: 'native' | 'plugin' | 'generated'
  source: string                // 'work-desk' | 'plugin:<pkg>' | 'ai'
  title: { zh: string; en?: string }
  description?: { zh: string }
  sizes: AtomSize[]             // 允许的档位
  defaultSize: AtomSize
  reads?: string[]              // 声明的数据依赖：calendar.events / mail.unread / quote.sh600519
  writes?: string[]             // 允许的写入面（默认空 = 只读原子）
  props?: JSONSchema            // 可配置项，设置面板自动生成
  permissions?: Permission[]    // network:<host> / dsh.tools:<name> / clipboard …
  skeleton?: AtomSize[]
  entry?: string                // plugin/generated 原子的实现入口
  version: string
}

interface AtomInstance {
  id: string                    // 实例 id
  atom: string                  // manifest.id
  size: AtomSize
  order: number
  props: Record<string, Json>   // 与 manifest.props 校验
  pinned?: boolean
  zone?: 'strip' | 'grid'       // 收起态是否露出
}
```

**三条硬规则**

1. **原子只描述自己要什么，不自己取数**：`reads` 交给 `DataBroker`，Host 统一缓存（TTL、memo、失败保留旧值）。这样才有了"换布局不重拉、多原子共享一次请求"。
2. **写操作必须声明 `writes`**，且落到 `applyOps` 白名单；没有 `writes` 的原子在 UI 上只读。
3. **`permissions` 逐项可审计**：`network:<host>` 由 Host 代发并校验白名单（借 FullWidget），`dsh.tools:<name>` 表示允许该原子调用某个已注册工具（借 dsh-web 的权限基线）。

### 3.2 插件怎么变成原子（这是"支持任何插件"的关键）

分三档，能力递减，覆盖面递增：

| 档 | 条件 | 得到什么 |
|---|---|---|
| **A. 声明式** | 插件 `package.json` 里加 `dsh.atoms: "./atoms.json"` | 完整原子：自定义渲染、设置、权限、数据 |
| **B. 工具卡** | 没声明，但有工具 | 自动生成「工具卡原子」：卡片 = 工具的 `output.render` + 一个"运行"按钮（参数表单从 `parameters` 生成） |
| **C. 面板帧** | 只有整页面板 | `frame` 原子：iframe 指向插件的路由（`/work-desk/atom-frame?src=...`），尺寸档位受限 |

`atoms.json` 与 `widget.json` 同构：

```json
{
  "atoms": [{
    "id": "dsh-email.unread",
    "title": { "zh": "未读邮件" },
    "sizes": ["1x1", "2x1"],
    "reads": ["mail.unread"],
    "props": { "type": "object", "properties": { "limit": { "type": "number", "default": 5 } } },
    "permissions": ["dsh.tools:email_list"]
  }]
}
```

自动发现：Host 启动时 `ctx.inventory`/profile 列表 → 扫每个已装包的 `dsh.atoms` → 校验 manifest（未知键报错，借 dsh-widgets 的 gen-registry 纪律）→ 注册。没有 `dsh.atoms` 但有工具 → 走 B 档，**用户零配置也能把任意功能摆上岛**。

### 3.3 Agent 改界面：`island_*` 工具面

| 工具 | 作用 | 备注 |
|---|---|---|
| `island_list` | 列出原子与当前布局 | 给模型看"现在长什么样" |
| `island_add` | 把某个原子加到岛/栅格 | 参数：atom、size、zone、props |
| `island_move` | 调整顺序/位置 | 传 instanceId + 目标 order |
| `island_resize` | 换档 | 必须在该 manifest 的 `sizes` 内 |
| `island_update` | 改 props | 按 `props` schema 校验 |
| `island_remove` | 移除 | **必须 `confirm: true`**（沿用既有删除闸门） |
| `island_generate` | 生成式卡片 | 见 3.4，返回 atom id |

全部走 `applyOps`：白名单、回执、撤销一致。模型说「把邮件未读和茅台价格放一个 2x1 的岛」→ 两次 `island_add`，用户在界面上看到岛长出来，还能 Ctrl+Z 撤回。

### 3.4 生成式 UI：三层，逐层放开

**L1 模板 + 参数**（默认开）：Host 内置模板（`metric-row` / `list` / `timeline` / `bar` / `kv`），模型只选模板 + 填数据。可预测、可测。

**L2 结构化 DSL**（默认开，需校验）：模型输出组件树，服务端按 schema 校验后存为 generated 原子。

```json
{ "type": "stack", "gap": 8, "children": [
  { "type": "text", "value": "今天 2 个会", "size": "title" },
  { "type": "metric", "label": "茅台", "value": "{{quote.sh600519.price}}", "trend": "{{quote.sh600519.changePct}}" },
  { "type": "list", "items": "{{calendar.today}}" }
]}
```

渲染器是**白名单组件集**（Stack/Grid/Text/Metric/List/Timeline/Badge/Sparkline/Button），**没有 HTML、没有事件脚本、没有 eval**；`{{...}}` 只能引用 `reads` 声明的数据。这一点比"让模型写 HTML"安全一个量级。

**L3 沙箱 HTML/SVG**（opt-in）：用户显式允许后，generated 原子可带 HTML，跑在 `iframe sandbox="allow-scripts"` + CSP（`default-src 'none'; style-src 'unsafe-inline'; img-src data:`），通过 postMessage 调 SDK（settings/storage/fetch 白名单）。等同 FullWidget 的第三方组件体验。

生成物带**溯源**：`{ model, prompt, revision, createdAt }`，可"重新生成/锁定版本"，避免模型漂移把用户的卡片改坏。

### 3.5 灵动岛的形态与动效

- **收起态**：屏幕正中一行胶囊（高 44–56px），放 3–5 个 `zone: 'strip'` 的原子，横向滚动；有新数据时胶囊"呼吸"一下（借 media-desk 的 breathe）。
- **展开态**：向下展开成栅格（`repeat(auto-fill, minmax(base, 1fr))`，档位 `1x1/2x1/2x2/2x4`），悬浮放大（借 dsh-widgets 的 `WAVE_SPRING`），拖拽换位（沿用工作台日历的 15 分钟吸附思路，改成 8px 网格吸附 + 松手回弹）。
- **空间纪律**：岛只在对话列内，宽度预算 = 对话列宽 − 正文 measure − 内缩；单列放不下时退化为底部抽屉。绝不挤压正文。
- **焦点**：点开某个原子 → 浮层内直接展开完整视图（邮件原子点开 = 三栏邮件页），关闭回到岛。

### 3.6 数据、状态、同步

- **持久化**：`$DSH_HOME/work-desk/island.json`（布局 + 实例 + props），`atoms.json` 只读注册表缓存；原子私有数据走 `AtomInstance.storage`（每实例一个 namespace）。
- **同步**：Host 权威 + 客户端订阅（SSE `/work-desk/island/stream`），变更带 `rev`，客户端乐观更新后以 `rev` 收敛；离线时只读。
- **取数**：`DataBroker` 按 `reads` 聚合，同一 key 只发一次请求，TTL 分级（行情 3s、邮件 60s、日程 30s、生成物 永久）。
- **失败**：原子级错误边界，单卡失败显示"重试"，不影响整岛。

### 3.7 安全

- 原子 manifest 是**不可信输入**：未知键拒绝、props 走 schema 校验、`permissions` 未授予时能力直接不可用。
- generated L2 无脚本；L3 在 iframe 沙箱内且 CSP 默认拒绝。
- 所有写操作过 `applyOps` + 回执 + 撤销；删除类必须 `confirm`。
- 外部网络请求只走 Host 代发，host 白名单可审计。

## 4. 与现有办公工作台结合：分阶段落地

现有 `dsh-work-desk` 已经具备：Host 权威 store、`applyOps` 白名单/回执/撤销、5 个语义工具、`/work-desk/*` 路由、会话镜像、71 个用例。**它天然就是 Island Host 的第一版。**

| 阶段 | 内容 | 产出 |
|---|---|---|
| **M0 契约** | `src/island/manifest.js`（校验器）、`registry.js`（builtin + 扫描 `dsh.atoms`）、`island.json` 持久化 | 单测：manifest 校验、非法键拒绝、迁移 |
| **M1 岛形** | `client/island/strip.jsx`（胶囊）+ `grid.jsx`（栅格）+ 拖拽/档位；`zone` 切换 | 截图：收起/展开两种形态 |
| **M2 首批原子** | 把现有能力拆成原子：`today.agenda`、`today.tasks`、`mail.unread`、`market.watch`、`brief`、`alert`；原四页保留为 `frame` 原子 | 岛里能摆出"今天" |
| **M3 Agent 面** | `island_*` 6 个工具接进现有 `tools.js`，复用 `applyOps` | 对话里说一句，岛实时变化 |
| **M4 生成式** | L1 模板 + L2 DSL 渲染器 + `island_generate`；生成物可锁定 | "给我一张本周邮件概览" |
| **M5 插件适配** | A 档 `dsh.atoms` 发现、B 档工具卡自动生成、C 档 iframe 帧 | 任意插件上岛 |

**M2 的原子清单（第一版就够用）**

| 原子 | 尺寸 | reads | 说明 |
|---|---|---|---|
| `work-desk.agenda` | 2x2 / 2x4 | `calendar.today` | 今日议程，进行中高亮 |
| `work-desk.tasks` | 2x2 | `tasks.open` | 待办勾选 |
| `mail.unread` | 1x1 / 2x1 | `mail.unread` | 未读计数 + 前 3 封 |
| `market.watch` | 2x1 | `quote.*` | 自选横条 |
| `work-desk.brief` | 2x2 | `brief.latest` | 晨报 |
| `work-desk.alert` | 1x1 | `alerts` | 提醒数 |

之后每加一个能力 = 加一个 manifest 单元 + 一个 render，注册表自动发现——和 dsh-widgets 的纪律一致。

**与对话的关系**：岛挂在 `conversation.input.overlay` 之上（借 dsh-widgets 的 slot 选择），收起态浮在输入框上方，展开态覆盖正文但保持对话可读；点开原子进浮层，不打断会话。

**迁移不破坏现有体验**：`dsh-work-desk` 的四个页面继续存在（变成 `frame` 原子的"全屏"形态），岛是新增的一层。用户不装岛也能用现在的工作台。

## 5. 风险与取舍

| 风险 | 说明 | 对策 |
|---|---|---|
| 岛挤压正文 | dsh-widgets 明确踩过 | 继承空间契约：预算由产品变量算，放不下退化抽屉 |
| 任意插件上岛不可控 | C 档 iframe 可能很重 | 默认 A/B 档；C 档需用户显式允许 + 限制尺寸档位 |
| 生成式 UI 质量不稳 | 模型写的结构会翻车 | L1 模板优先；生成物可锁定/重生成；渲染器白名单 |
| Host 权威延迟 | 每次改布局一次往返 | 乐观更新 + `rev` 收敛；批量提交（一次拖拽只提交终态） |
| 状态爆炸 | 多原子 × 多实例 | 布局与数据分离；原子私有数据按实例 namespace 懒加载 |
| 插件契约漂移 | 第三方 `atoms.json` 字段乱写 | 构建期/运行期双重校验，未知键拒绝（dsh-widgets 的做法） |
